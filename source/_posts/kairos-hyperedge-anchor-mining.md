## TL;DR

Kairós 的知识图谱上叠了一层推理链超图：把 `A -[p1]-> B -[p2]-> C` 的两跳路径物化成超边，供查询时做结构性检索增强。v1 版本挖出了 **137,257 条**链，看着很繁荣。

直到我把样本打出来给图谱的"本人"看——

```text
居委会 ──[辱骂]──> 梦时空 ──[学习]──> 计算机导论    (conf=0.52)
1beromok ──[索要礼物]──> 梦时空 ──[位于]──> 宜都区   (conf=0.26)
```

两件事各自都是真的，但拼在一起什么都不是。这篇记录改造全过程：**最终 2,548 条，63% 置信度 ≥ 0.7**，每一条都能读。

## 一、v1 的三个设计缺陷

### 缺陷 1：弱谓词当粘合剂

谓词分了三档：强知识（属于/就读于/购买…）1.0 分、事件（游玩/参加/前往…）0.6 分、噪音（提及/回复/艾特…）0 分，**未知谓词给 0.25 的"鼓励分"**。

这个鼓励分是灾难。「辱骂」「调侃」「索要礼物」这些互动动词全从噪音档漏进了鼓励档，成了链条的合法粘合剂。

### 缺陷 2：人名当中转

`辱骂你 → 你学C语言` 能成链，是因为中间节点"你"同时挂着这两种边。**人名是最差的超边中转**——一个活跃群友什么都干，经过他的任意两条边都能接起来。真正的知识链中转应该是机构、地点、产品这类强类型锚点。

### 缺陷 3：n_pos 是个假指标

重挖时同签名 MERGE 会 `n_pos + 1`，本意是"证据累积"。但挖掘端本来就按签名去重，每次输出恰好一条——所以 n_pos 实际记录的是**重挖次数**，和证据毫无关系。"就读于鄂高"显示 n=32，不是因为 32 个独立信源，而是我重启了 32 次挖掘。

## 二、改造：三条硬规则

新规则全部前置到 SQL 层：

```sql
WHERE r1.predicate IN (强知识 ∪ 事件)     -- 白名单，不再有鼓励分
  AND r2.predicate IN (强知识 ∪ 事件)
  AND e2.type IN ('机构','地点','事件','产品',
                  '项目','技术','会议','领域')  -- 锚点类型约束
```

配套改动：

- **n_evidence 取代 n_pos**：挖掘时同一签名每多一条底层关系边支撑就 +1，这才是真实的证据权重；
- **玩笑链置信度减半保留**（is_playful 标记），娱乐检索有价值但不许冒充事实；
- **时间区间取两跳交集**（Zep 风格 t_valid），区间矛盾的链直接丢弃。

## 三、效果对比

| 指标 | v1 | v2 |
|---|---|---|
| 总量 | 137,257 | **2,548** |
| 高置信占比 | ≈0% | **63% ≥ 0.7** |
| 中转节点类型 | 人名泛滥 | 机构974/产品913/地点394/技术84/事件80 |
| 玩笑链 | 35,075 条污染 | 144 条且置信减半 |

v2 的典型产出：

```text
博士 ──[属于]──> 愚人众 ──[属于]──> 原神              (0.89)
sd ──[位于]──> 高三15班 ──[位于]──> 鄂州             (0.89)
我 ──[就读于]──> 鄂高 ──[属于]──> 985工程             (0.85, ⏰2023-09~2026-06)
```

最后一条尤其值钱：单条关系只能回答"在哪上学"，超边把**地理归属和组织属性**一并编码，还带时间窗——这是检索增强时真正能提升答案质量的结构。

## 四、事故：边删边写的幽灵进程

重建过程本身踩了两脚。

第一脚：Neo4j 事务内存只有 358MB，一条 `MATCH (h:HyperEdge) DETACH DELETE h` 删 13.7 万节点直接 `MemoryPoolOutOfMemoryError`。改成每批 5000 的循环删除，14 秒清完：

```cypher
MATCH (h:HyperEdge) WITH h LIMIT 5000
DETACH DELETE h RETURN count(h)
```

第二脚更阴险：删干净后数字总是对不上——保存 2,548 条，库里却有 4 万条且持续增长。排查发现 **kairos 服务进程还缓存着旧版挖掘代码**，它有一个数据同步后的自动重挖钩子（`auto_resync`），正用旧规则源源不断地把垃圾链写回来。

文件系统上的代码是新的，内存里的代码是旧的。`docker restart` 之后世界清净。教训：**凡是带后台自愈/自动补偿机制的系统，改完逻辑必须重启所有可能持有旧逻辑的进程，否则你在和自己的幽灵作战。**

## 五、人的反馈是最好的评测

重建完成后我把样本发给图谱里的当事人核对，收到的回复："我就读于内蒙古大学是假的，其实是湖北大学。"

这条反馈暴露的不是挖掘问题而是抽取问题——某几个窗口里的玩梗（保研北大、贬低复旦、三非大学……同一批抽出来的全家桶）被当成了真实学历。处置：

```python
# 事实性错误 → 硬删
DELETE FROM relations WHERE id IN (湖南大学, 内蒙古大学的边);
# 玩梗 → 降级为 playful,置信度压到 ≤2,不再进入任何严肃推理
UPDATE relations SET is_playful=1, confidence=MIN(confidence,2) WHERE id IN (...);
# 真实学历 → 提满置信度,时间窗开口朝向未来
UPDATE relations SET confidence=10 WHERE ... 就读于→湖北大学;
```

这给我上了重要一课：**自动化管线再精密，也需要一条人工纠错的高速通道**——而且纠错成本必须低到当事人一句话就能完成。目前 Kairós 的做法是把这类反馈直接落成 SQL 补丁脚本，未来计划做成 bot 命令（"这条信息是假的" → 自动降权）。

## 六、还没做完的事

现在的超边仍是"两跳路径"，严格说不是图论文意义上的超边（一条边连接 n≥3 个实体）。真正的下一步是**事件星型挖掘**：以「肯德基聚餐」「跨年开趴」这类事件实体为中心，把 n 个参与者的关系物化成真正的 n 元超边——群聊里天然全是多人事件，那才是超图相对普通图的增量所在。等做完了再写一篇。
