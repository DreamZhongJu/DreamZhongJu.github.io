预训练模型提供的是通用语言表示，微调（Fine-tuning）则让这些表示对具体任务真正有用。关键不只是“在 BERT 后面接一个分类头”，而是先明确任务需要判断什么，再选择读哪一层、哪一个位置的表示，并决定哪些参数应该随任务数据更新。

## 一、从预训练到下游任务

以 BERT 为例，预训练通常使用 Masked Language Modeling（MLM）：随机遮住一部分 token，要求模型根据双向上下文恢复它们。

```text
The cat sits on the [MASK]
              ↓
预测：mat
```

这让模型学习词义、句法和上下文依赖，但它没有直接学会“这是一条正面评论”“这个 token 是实体边界”或“两个人物之间是什么关系”。下游微调在任务数据上定义新的损失，将梯度传回表示模型，使其内部表征偏向目标任务的判别边界。

```text
预训练 Encoder → 任务表示 → Task Head → Loss
                    ↑                    │
                    └──── 反向传播 ──────┘
```

## 二、Feature Extraction 与 Fine-tuning

### 1. Feature Extraction：冻结 Encoder

特征提取将预训练 BERT 当作固定的向量生成器：

```text
文本 → 冻结的 BERT → CLS / token / pooled representation → 可训练分类器
```

只有分类头更新，训练速度快、显存占用低，也能在数据很少时减少过拟合风险。但 encoder 不会为任务修正注意力模式与特征空间；若预训练表示与领域或标签边界差距较大，分类头能弥补的空间有限。

### 2. Full Fine-tuning：端到端更新

全量微调让 Transformer 全部参数和任务头共同更新：

```text
文本 → BERT → 表示 → 分类头 → loss
          ↑_____________________│
              所有层参与更新
```

它通常能获得更高的任务上限，因为模型可以学习“情感词应被重视”“实体两侧的上下文更关键”等任务特定模式。代价是训练资源、模型版本和过拟合风险都更高；学习率通常需要远小于从头训练时的学习率，以避免快速破坏已有预训练能力。

| 策略 | 更新参数 | 适合情形 | 主要代价 |
| --- | --- | --- | --- |
| Feature Extraction | 只有任务头 | 快速基线、资源有限 | 表示无法适应任务 |
| Full Fine-tuning | 全部 Encoder + 任务头 | 数据与资源充足、追求性能 | 成本高，需谨慎调参 |
| Partial Fine-tuning | 部分高层 + 任务头 | 中等资源、领域偏移有限 | 需选择解冻层数 |
| PEFT（如 Adapter/LoRA） | 小量新增或低秩参数 | 多任务部署、存储受限 | 容量与配置需要评估 |

参数高效微调并不改变“任务损失塑造表示”的基本逻辑，只是用较少可训练参数实现适配，方便一个基座模型服务多个任务。

## 三、任务决定读取哪种表示

Transformer 为每个 token 生成 hidden state。下游任务的预测单位不同，所读取的表示也不同：

| 任务 | 预测对象 | 常用表示 | 任务头 |
| --- | --- | --- |
| 文本分类/情感分析 | 一段文本 | `[CLS]` 或 pooled sentence representation | 句级分类器 |
| NER/词性标注 | 每个 token | 每个 token 的 hidden state | token-level 分类器 |
| 关系抽取 | 实体对 | 两个实体/mention 的组合表示 | relation 分类器 |
| 语义检索 | 查询与文档 | Pooling 后的文本向量 | 相似度或对比损失 |

### 文本分类为什么常用 `[CLS]`

输入通常带有特殊位置：

```text
[CLS] Apple released iPhone [SEP]
```

最后层的 `h_CLS` 经线性层映射到标签 logits：

<div class="attention-formula" role="math">logits = W · h<sub>CLS</sub> + b</div>

`[CLS]` 并非天然的“句子摘要”，而是在分类目标的梯度持续作用下，被训练成承载整句判别信息的位置。不同预训练模型和任务也可采用 mean pooling 或其他聚合方式，不能把 CLS 当作唯一正确答案。

### NER 为什么要读 token 表示

命名实体识别要逐 token 判断标签：

```text
Apple released iPhone in China
Apple → ORG；iPhone → PRODUCT；China → LOC
```

因此每个 token 的 hidden state 分别进入分类器。若原始词被 tokenizer 切成多个 subword，还需要定义标签如何对齐，常见做法是仅对一个词的首个 subword 计算损失，避免同一标签被重复计数。

### 关系抽取为什么要用实体级表示

关系抽取关心特定实体对，例如“Steve Jobs founded Apple”。直接拿整段文档的 CLS 可能丢失实体位置、mention 上下文和指代线索。常见流程是先得到 mention 表示，再汇聚为实体表示，最后组合实体对：

```text
mentions → entity A representation
        → entity B representation
        → [A, B, A⊙B, context] → relation classifier
```

任务头的输入应该与预测对象同粒度；这是比“使用哪一个模型名字”更重要的设计原则。

## 四、冻结与解冻：低层不是永远不该动

常见经验认为低层更偏向词法和局部模式，高层更偏向语义和任务信息，因此可以冻结较低层、只微调高层。这是一个有用的资源折中，但不是固定规律：不同模型、语言、领域和任务的层级功能会不同。

可将解冻层数视为待验证的超参数。实践中应同时观察训练集与验证集曲线：训练效果提升而验证集下降，可能意味着数据过少、学习率过大或模型适配过强；冻结更多层、使用更小学习率、早停或 PEFT 都可能更合适。

## 五、领域继续预训练：先学领域语言，再学任务标签

当通用预训练语料与目标领域相差很大时，可先在无标注领域文本上继续 MLM 训练（Domain-Adaptive Pretraining），再进行下游微调：

```text
通用预训练模型
  → 领域语料上的继续 MLM 预训练
  → 领域适配的 Encoder
  → 有标注下游任务微调
```

医学、法律、金融、代码或特定科学领域都有大量专有术语、文体与缩写。继续预训练能让模型先适应这些分布，再让有限的标注数据集中学习标签边界。

它也有风险：领域语料质量差、分布过窄或训练过度时，模型可能遗忘一部分通用能力。应保留通用与领域验证集，并把继续预训练视为有评测支持的假设，而非必经步骤。

## 六、小样本场景：SetFit 的思路

SetFit 将分类数据改造为句子对，先用对比学习让同类样本靠近、异类样本远离，再在得到的句向量上训练轻量分类器：

```text
少量带标签样本
  → 构造同类/异类 pair
  → 对比学习适配 Sentence Transformer
  → 固定或轻微更新 embedding
  → 训练分类器
```

它连接了第十章的 embedding 训练与本章的分类任务。小样本并不等于无需严谨划分数据：如果从同一原始样本派生的句对同时落入训练和验证集，会产生数据泄漏，让结果看上去异常乐观。

## 七、训练与评测中的常见陷阱

- **标签不平衡**：仅报告 accuracy 可能掩盖少数类完全失效，应同时看每类 precision、recall、F1 或宏平均指标。
- **数据泄漏**：重复文本、同一文档的相邻片段或未来数据进入训练集，会让离线指标失真。
- **任务头与标签不匹配**：多标签任务需要独立 sigmoid/BCE 类目标，不能误用单标签 softmax。
- **只看最终分数**：应检查错误样本，分清是 tokenizer、领域术语、实体边界、长文本截断还是标签定义造成的问题。
- **忽略校准与阈值**：分类概率用于自动化决策时，需要在验证集上选择阈值并评估置信度，而不只是取 argmax。

## 八、本章总结

```text
预训练：获得通用语言表示
继续预训练（可选）：适应领域语言分布
微调：用任务损失调整表示和任务头
任务表示：句级、token 级、实体级或 pooled 向量
评测：按预测单位与真实风险检查性能
```

微调的本质是让表示空间服务于具体决策。先定义任务的预测对象和错误成本，再决定使用哪种表示、更新哪些参数、是否需要领域适配，才能让预训练模型真正落到可靠的下游系统中。
