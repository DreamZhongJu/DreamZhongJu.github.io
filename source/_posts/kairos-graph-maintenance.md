## TL;DR

Kairós 的知识图谱由 8 个 QQ 群的 456,888 条消息增量构建而成（2022-06 → 2026-08）。上线两个月后体检发现：**6,988 个实体里 98% 是"裸名字"**（靠字符串去重，没有身份锚点），1,328 个裸人名碎片化地描述着同一批人，合并过的旧名还会被 LLM 重新抽取、反复重建节点。

这周给图谱装上了"自我维护"机制：

- **每日自动共指消解**：注册表层 + 模糊层的两级合并，配三层保护名单
- **防爆炸四道闸**：入口过滤、镜像瘦身、合并防回退、健康报告
- **首次运行**：自动合并 15 个碎片节点，人工拍板再并 3 个，零误合并

干跑阶段救了三类命：**9 个亲属称谓误判**（"爱sei的表哥"差点并进爱sei）、**"姓余"误判**（名片后缀被当成人）、**否定式名片误判**（"杨某康但不是杨永康"差点吞掉杨永康）。

## 一、图谱是怎么"膨胀"的

### 症状体检

```
实体构成(6,988):  产品 2,068 / 人名 1,475 / 事件 928 / 地点 735 / 技术 626 ...
qq: 锚点人物        148     ← 身份骨架,健康
裸实体(非锚点)      6,834   ← 98%,靠名字规范化去重
孤立实体(零关系)    316     ← 纯垃圾节点
单字名 / 占位名     53 + 群成员\d+ 若干
关系重复三元组      0       ← 去重一直生效
无溯源关系          1,652 (7%)
```

增量其实不算快（每天约 40 个实体），真正的病根有两个。

### 病根 1：合并回退环（cherry 循环）

手工合并「cherry（恩师 姓余.）」到锚点人物后，第二天它又出现了。因为**合并只改写了实体表，没有记录"cherry 这个名字已经属于谁"**——消息里再出现 cherry，LLM 照常抽取，裸节点照常重建。旧名没有"记忆"，合并就永远是一次性的。

### 病根 2：共指碎片化

同一人在不同时期的名片是「东北雨姐」「雨姐」「cherry（恩师 姓余.）」，群友口嗨还有「刘奶龙」「懒奶龙」「k奶龙」的变体。148 个锚点人物之外，1,328 个裸人名节点各说各话，问答时"雨姐是谁"和"东北雨姐是谁"命中不同的节点。

### 为什么不敢直接自动合并

这个群的历史上出过事故：把「灵梦」（东方角色）并进过网名叫灵梦的真人。**QQ 群的戏称、角色名、亲属称谓全是合法的人名**，字符串相似度会给出漂亮的高分，然后犯下不可逆的错误。

## 二、设计：证据分层 + 三层保护

### 证据分层（T1 / T2 / T3）

| 层 | 证据来源 | 处置 |
|---|---|---|
| T1 权威 | `coref_overrides.json` 手动断言、已注册别名 | 自动合并 |
| T2 昵称史 | `nickmap.json` 名片历史（谁曾经叫过什么） | 只进审阅队列 |
| T3 模糊 | 字符串包含 / 相似度（≥0.95 自动，0.88–0.95 审阅） | 高分自动，低分审阅 |

T2 刻意不自动：昵称史能证明"某人叫过这个名"，但**证明不了消息里的这个名字指的是他**——这正是当年灵梦事故的根源。

### 三层保护（硬约束）

1. **硬名单**：大师中的大师（qq:2918738718）、老蒯、小刘系——永不并入任何人，也永不被并入
2. **保护名**：`coref_overrides.json` 中空值条目 = "此名字永不合并"（23 个东方角色名全在这里）
3. **亲属排除**：`X的妈妈/表哥/亲爹/老父亲`、`的舅/的姑/的爷`——亲属是**另一个人**，模式命中直接拒绝，连审阅都不进

### 合并防回退（治 cherry 循环）

合并发生时，旧名自动写入 `auto_aliases.json`：`{"cherry（恩师 姓余.）": "qq:2654526702"}`。mention 解析时以**最低优先级**叠加——手动断言 > 保护名 > 自动别名。旧名从此直接解析到锚点，**不再重建节点**。这个文件完全可审阅、可删除，是"机器干的活"和"人定的规矩"之间的一层透明缓冲。

## 三、实施：干跑救了三条命

所有改动先 `auto_apply=False` 干跑，把候选清单打出来人工过一遍。首轮 T3 出了 **24 个自动候选**，其中 9 个是错的：

```
❌ 1beromok的妈妈        → 1beromok      ← 妈是另一个人!
❌ 爱sei的表哥/姑爹/舅    → 爱sei         ← 亲戚是另一个人!
❌ 群底层fvv的爷爷/父亲   → 群底层fvv
❌ AAA木头收藏康哥的弟弟  → AAA木头收藏康哥 ← 你弟弟不是你!
❌ 姓余                  → 小师（恩师 姓余.） ← "姓余"是名片后缀,不是人
```

### 补丁 1：亲属称谓正则

`X的妈妈/表哥/亲爹/老父亲` 全部进入黑名单；单字亲属用 `的(舅|姑|姨|叔|伯|侄|甥|爷|奶|爸|妈|哥|弟|姐|妹)` 捕获（"爱sei的舅"漏网就是因为它只有"的舅"两个字）。**目标侧**也要查——`zj → zj的老父亲` 这种，裸名干净、目标名是亲属角色，同样危险。

### 补丁 2：姓X 模式

`^姓[一-龥]$` 直接拒绝——"姓余/姓王"是群里几十张名片的公共后缀，不是实体。

### 补丁 3：否定式名片降级

`杨某康 → 杨某康但不是杨永康（恩师 姓余.）` 相似度 0.962，看着该并。但名片**白纸黑字写着"但不是杨永康"**——杨永康是另一个人（或者至少名片主人坚持他是）。规则：目标名含 `但不是|不是|并非` → 一律降级审阅，永不自动。

补完后复验：**AUTO 10 个全是同人名片变体，REVIEW 3 个**。

## 四、防爆炸四道闸

| 闸 | 位置 | 作用 |
|---|---|---|
| 入口过滤 | `extract.py` | 长度<2、纯 emoji、`群成员\d+`、纯标点不再实体化 |
| 镜像瘦身 | `graph_store.sync_all` | Neo4j 只镜像"有关系或锚点"的节点；零度垃圾留在 SQLite（全量真源） |
| 合并防回退 | `coref.register_merge_alias` | 旧名 → 自动别名库，永不重建 |
| 健康报告 | `graph_health.py` | 每日输出实体增速/孤立数/裸人名占比/无溯源占比，超阈值告警 |

关键取舍：**SQLite 是全量真源，Neo4j 是检索镜像**。孤立实体、单字名不删除（历史完整），只是不再进活跃图。

## 五、落地结果

```
首轮自动合并:   5(T1) + 10(T3) = 15 个裸节点 → qq: 锚点
人工拍板再并:   我要玩玩原神→我要玩原神(错字)
               杨某康→杨某康但不是杨永康(91 条关系)
               杨永康→杨某康但不是杨永康(4 条关系)
auto_aliases:  15 → 18 条(旧名全部有"记忆")
裸人名:         1,328 → 1,313
Neo4j 镜像:     7,003 → 6,661 实体(340 个零度/垃圾节点退出镜像)
调度:           每日 03:30 自动 sweep + 重挖超边
               每周日 03:45 无溯源会话关系清理
```

### 调度器挂载（APScheduler）

```python
# 每日 03:30: 共指 sweep → 镜像同步 → 超边重挖 → 健康报告
scheduler.add_job(run_graph_maintenance, CronTrigger(hour=3, minute=30))
# 每周日 03:45: 清理无溯源会话类关系(提及/回复/艾特/调侃/吐槽/询问)
scheduler.add_job(run_weekly_cleanup, CronTrigger(day_of_week="sun", hour=3, minute=45))
```

无溯源清理只动"会话机制类"谓词——它们在原文 chunks 里随时可恢复；语义谓词（游玩/位于/属于）永不删。

## 六、踩坑记录

1. **合并本身会制造新问题**：`merge_entity` 重指向关系后，旧名如果不注册别名，下一轮抽取又把它建回来——"合并防回退"不是优化，是必需品。
2. **相似度的幻觉**：包含关系给 0.95+ 的分数，"杨某康"包含在"杨某康但不是杨永康"里是 0.962——**高相似度证明不了同一个人，只能证明字符串长得像**。
3. **容器里没有 python**：改 koishi 配置时发现容器是精简镜像，最后用行号 + sed 精准删除，比绕道装 python 快得多。
4. **SSH 会话超时**：Neo4j 全量同步（2 万+ 节点）超过 SSH 行超时，客户端读超时会把服务端进程也带走——长任务一律 `nohup ... &` 分离执行 + 日志轮询。

## 七、后续

- 审阅队列机制已就位：以后每天只会有真正模糊的候选进队列（比如错字、否定卡），人工看一眼即可
- 旧垃圾（53 个单字名、313 个孤立实体）保留在 SQLite 不进镜像，等健康报告观察趋势再定清理策略
- 想再进一步：昵称史（T2）与消息共现统计结合，把"曾经叫过"升级为"大概率指代"——但那是下一个事故的温床，慎动

图谱终于学会了自己维护自己。而它学到的第一课，是**永远不要把亲戚并进本人**。
