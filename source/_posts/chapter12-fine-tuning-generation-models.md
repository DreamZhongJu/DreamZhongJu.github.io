基础语言模型会预测下一个 token，却不天然是一个可靠的聊天助手。微调生成模型的目标是让已有的语言能力适配明确的交互接口、领域任务和输出约束，同时尽量避免高昂的训练与部署成本。

## 一、Base Model 的能力与边界

自回归预训练优化的是在前文条件下预测下一个 token：

<div class="attention-formula" role="math">P(x<sub>t</sub> | x<sub>&lt;t</sub>)</div>

训练数据通常来自网页、书籍、论文和代码。这个目标使模型获得语言模式、代码与知识的统计关联，但不会自动告诉它：哪段文本是用户指令、回答应在何处结束、多个可行回答中人更偏好哪一种，或工具调用必须符合什么协议。

```text
Base Model：擅长延续文本
Instruction/Chat Model：擅长将用户请求作为任务并给出符合约束的回应
```

两者的底层生成机制相同，差别主要来自后训练数据、模板、优化目标和安全/产品层的约束。

## 二、常见的后训练链路

将现代 LLM 训练过程简化为下面三段是有帮助的，但不同模型的实际配方可能交错、重复或加入更多阶段：

```text
大规模文本 → Pretraining → Base Model
指令—回答数据 → SFT → Instruction Model
偏好比较数据 → Preference Optimization → 更符合目标偏好的模型
```

### 1. Pretraining：学习广泛的语言先验

预训练数据覆盖广、规模大，目的在于建立通用能力。它代价最高，通常不是单个领域项目的首选手段。若目标只是让模型遵守某种格式或熟悉内部任务，优先考虑 RAG、Prompt、SFT 或参数高效微调。

### 2. SFT：让模型学会任务接口

监督微调（Supervised Fine-Tuning）使用高质量的“输入—目标回答”示例。训练目标依然是 next-token prediction，只是训练序列从普通文本换成经过 Chat Template 格式化的指令数据：

```text
system: 你是技术助手。
user: 解释 Attention。
assistant: Attention 通过…
```

实际训练通常只计算 assistant 回答 token 的 loss，避免要求模型“预测”用户输入。SFT 可以教会任务格式、语气、工具调用 JSON、领域术语和示例中的决策方式；它不能补救错误、矛盾或覆盖不足的数据，反而会把这些问题放大到模型行为中。

### 3. Preference Optimization：在多个可行答案间表达偏好

很多请求不只有唯一正确答案。偏好数据通常给出同一 Prompt 下的 `chosen` 与 `rejected` 回答，让模型更倾向于前者，例如更准确、简洁、有帮助或符合安全要求的回答。

```text
Prompt + chosen answer + rejected answer
          ↓
学习：chosen 的相对偏好应更高
```

偏好对齐优化的是“在当前偏好数据与约束下更受欢迎的行为”，不能代替事实检索、领域评测或应用层安全控制。

## 三、RLHF 与 DPO：两种使用偏好数据的路线

RLHF（Reinforcement Learning from Human Feedback）常先用偏好比较训练 Reward Model，再通过 PPO 等强化学习方法优化生成模型，使其在奖励模型下获得较高分数。其优势是可以显式定义和优化奖励信号，代价是流程复杂、训练稳定性与奖励投机都需要额外处理。

DPO（Direct Preference Optimization）直接根据 chosen/rejected 数据调整策略模型的相对概率，通常不需要单独训练并在线使用 Reward Model。

| 路线 | 主要步骤 | 优点 | 主要挑战 |
| --- | --- | --- | --- |
| RLHF | 偏好数据 → Reward Model → 强化学习优化 | 可显式建模奖励、灵活扩展 | 训练链复杂，易受奖励模型偏差影响 |
| DPO | 偏好数据 → 直接优化模型偏好 | 实现相对简洁、训练稳定性较好 | 强依赖偏好对的覆盖与质量 |

无论选哪种方法，都需要保留一个参考策略或约束，避免模型为了偏好分数而过度偏离原有能力。最终质量取决于偏好标注准则是否清晰、样本是否覆盖真实失败模式，而不是算法名称本身。

## 四、全量微调为什么昂贵

Full Fine-tuning 会更新模型所有参数。训练时除了权重本身，还要保存梯度、优化器状态和中间激活；模型越大、序列越长、batch 越大，显存压力越高。每个任务若保存一份完整权重，也会增加存储和部署成本。

全量微调在数据规模足够、任务与基座模型差异很大，或需要最大任务上限时仍有价值。但多数领域适配和原型项目，应先评估参数高效方案是否已经满足目标。

## 五、PEFT：只训练任务所需的少量自由度

参数高效微调（PEFT）冻结大部分 base model，只训练少量新增或选定参数。常见方式包括 Adapter、Prefix/Prompt Tuning 与 LoRA。它们共同的工程价值是：训练显存更低、任务增量更小、同一基座模型可以挂载多个适配器。

### LoRA：用低秩增量表示权重更新

对于原始权重 (W)，全量微调需要学习同形状的更新 (ΔW)。LoRA 假设该更新可由两个低秩矩阵表示：

<div class="attention-formula" role="math">W' = W + ΔW = W + BA</div>

其中 (W) 冻结，(A) 和 (B) 的秩 (r) 远小于原矩阵维度。训练时只更新 (A/B)，推理时可在计算中叠加增量，或在部署前合并到权重。

LoRA 的秩、缩放系数、dropout 和目标模块决定其容量与训练行为。给所有线性层都加很大的 LoRA 不一定更好；应基于任务、资源和验证集比较不同配置。

### QLoRA：降低基座模型的加载成本

QLoRA 通常将冻结的 base model 以低比特量化形式加载，同时训练较高精度的 LoRA adapter。它主要降低基座权重占用的显存，使较有限的硬件也能适配更大模型。

量化不会消除激活、序列长度和 batch 带来的内存压力，也可能影响数值稳定性和最终质量。它是资源约束下的有效折中，而不是免费地获得全量微调效果。

## 六、一个可维护的 SFT/LoRA 工程流程

```text
1. 定义任务和可验收的输出格式
2. 收集、去重并审核 instruction—response 数据
3. 选定正确 Chat Template，并明确哪些 token 参与 loss
4. 加载 base model；按资源选择 Full FT、LoRA 或 QLoRA
5. 训练与验证，监控格式遵从、事实性和任务指标
6. 保存 adapter、训练配置、数据版本与评测集
7. 部署前决定运行时挂载 adapter 或合并权重
```

如果目标是关系抽取，训练样本应明确输入文档、实体范围、关系 schema 与无关系情况；输出最好采用可验证的结构化格式。若数据没有覆盖实体边界、跨句证据或负例，仅换 LoRA 参数无法补上这些任务定义缺口。

## 七、训练数据、RAG 与微调的分工

微调适合让模型学习相对稳定的行为：输出风格、领域任务格式、工具协议、抽取 schema 或经过反复验证的流程。RAG 更适合提供频繁更新、需要引用或不应写入权重的事实资料。

```text
稳定行为与格式 → SFT / Preference Optimization
最新、私有、需溯源的事实 → RAG
一次性的任务限定 → Prompt
```

不要把所有文档都拿去微调以“注入知识”。这既不保证精确记忆，也会失去引用、更新和删除的能力。先判断问题是知识缺失、任务格式不稳、检索失败还是数据质量不足，再选择相应手段。

## 八、评测：不能只看训练 loss

生成模型的训练 loss 下降，可能只说明模型更会模仿训练集。上线前还需要检查：

- 任务正确性：抽取、分类、代码或问答的可验证结果；
- 格式遵从：JSON/schema 能否解析，枚举和字段是否正确；
- 事实与引用：是否基于证据回答，是否在不知道时拒答；
- 泛化性：未见措辞、长输入、边界案例和多语言样本；
- 回归与安全：原有能力、权限边界和拒答行为是否退化。

固定测试集、保留失败案例并记录数据与 adapter 版本，才能判断一次微调究竟带来了改进，还是只让模型更贴合训练样本。

## 九、本章总结

```text
Pretraining：获得语言与广泛先验
SFT：学习指令接口、任务格式与高质量示范
Preference Optimization：学习多个可行答案间的目标偏好
LoRA / QLoRA：以较低成本为特定任务注入可切换的适配能力
RAG + Evaluation：为更新知识提供证据，并验证真实效果
```

生成模型微调的价值在于让强大的基座能力稳定地服务于具体任务。最关键的决策不是先选 PPO、DPO 或 LoRA，而是先写清楚目标行为、准备可审计的数据，并建立能够发现退化的评测闭环。
