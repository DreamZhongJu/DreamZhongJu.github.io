## TL;DR

我报名了开源之夏（OSPP）2026，申请了整整一个月：选定目标项目、本地跑通、复现 bug、提交真实 PR（其中一个已合入上游）、写了自认为扎实的申请书——**结果一个名额都没拿到**。

一个月里，我一度以为是申请书写得不够好。直到我把中选者的材料、我的申请书、以及 GitHub 上的真实轨迹放在一起对比，才看清真相：

> **这不是申请书写得好不好的问题，是一场"谁先让导师认可"的占坑游戏。** 热门项目的名额，在评审窗口之前，就已经被"提前在导师仓库里干过活、被导师认识"的人锁定了。申请书只是走流程，真正的竞争发生在 GitHub 上、发生在申请季开始之前。

我带着十几年的竞赛思维进来，用错了地图，打了一整局。

## 一、背景：我是"竞赛思维"长大的

我是在算法竞赛和机器人竞赛里长大的。参加过不少比赛，拿过全国总决赛一等奖。竞赛教会我的逻辑非常简单：

- **题目公开、规则统一**——每个人看到的题面一模一样；
- **提交即证明**——把作品交上去，评委看你跑出来的结果；
- **匿名评审、公平排名**——不看你人脉，只看你提交的东西。

这套逻辑在我的人生里屡试不爽：把作品做好，提交，等结果。所以我带着同一套逻辑走进了开源之夏。

**然后我被这套逻辑反噬了。**

## 二、我做了什么：看起来每一步都"对"

申请期间，我做的事在纸面上挑不出毛病：

1. **选定目标项目**——一个 AI/大模型方向、star 过万的热门开源项目（DB-GPT），方向是我熟悉的 Agent 与数据链路；
2. **本地跑通、复现 bug**——把项目在本地跑起来，找到了真实问题并验证；
3. **提交真实 PR**——围绕项目的一个真实 issue，提了 3 个 PR，其中 **1 个合入上游主分支**，另外 2 个进入了核心维护者的 review，拿到了"实现看起来正确"的评价；
4. **写申请书**——项目理解、技术方案、时间计划、验收标准，还做了本地原型验证。

我当时的想法和大多数申请人一样：**把技术做扎实，材料自然有说服力。**

## 三、残酷现实：坑早就被人占了

一个月后，结果公布——**零命中。**

一开始我怀疑是申请书的问题。于是我去翻项目页，逐个看那些我关注过的项目，发现一件让我后背发凉的事：

**那些热门项目的"中选学生"栏，在我开始卷 PR 之前、甚至在我提交申请之前，就已经有人了。**

我不是输在申请书写得不好。我是**入场太晚**——名额在评审窗口打开之前，就通过 GitHub 上的提前贡献和导师的直接接触被锁定了。我提交申请书的时候，这个坑已经被占完了。

## 四、核心洞察：OSPP 不是竞赛，是"信任先于作品"

这是我这一个月买到的最贵的一课。把竞赛和开源之夏放在一起对比，差异一目了然：

| 维度 | 竞赛（我熟悉的） | 开源之夏 OSPP |
|---|---|---|
| 评审方式 | 匿名打分，看提交结果 | 导师主观挑选，看人 |
| 竞争舞台 | 在赛场上（提交即见） | 在 GitHub 上（申请季之前） |
| 你的筹码 | 提交的作品本身 | 与导师/维护者建立的信任 + 可验证的协作痕迹 |
| 对手 | 一道公开的题 | 一个"早就在导师仓库里留痕"的人 |
| 关键信息 | 全部公开 | 藏在 issue、PR、邮件和群聊里 |

**竞赛拼"提交"，OSPP 拼"信任"。** 而信任只能靠提前、持续、可验证地在导师眼皮底下干活来积累——不是靠一份申请书，更不是靠临门一脚。

我卷的 PR 不是没用。它是入场券。但**我拿到入场券的方式错了**：

- 我卷的时机太晚——申请季已经白热化，维护者一天要处理好几条 PR，根本没空看我的；
- 我卷的内容是周边收尾修复，不是**导师项目本体的深挖**；
- 我卷完了 PR，却没有在导师面前"被记住"——没有提前对话，没有让导师把我当成"已经在帮他干活的人"。

所以当评审开始时，导师面前站着一群人：**提前几个月就在他仓库里贡献、跟他邮件往来过的人**，和一个"刚提交完 PR 就来申请的我"。他选谁，没有任何悬念。

## 五、我的五个具体失误（修正版）

按因果深度排序：

| # | 失误 | 说明 |
|---|------|------|
| 1 | **用竞赛逻辑理解申请** | 以为"卷够 PR + 写好申请 = 有戏"，其实名额靠提前占坑和导师认可，申请书只是签字 |
| 2 | **困在一个热门社区** | 我全部押在 DB-GPT 这种 star 过万的现象级项目上——这是卷王赛道，早被内定，月后才进，天然陪跑 |
| 3 | **卷的时机和对象都不对** | 申请季白热化时卷的是周边小修，而不是导师项目本体的深挖；维护者根本没空 review |
| 4 | **缺"让导师认识我"的动作** | 竞赛不需要认识裁判，OSPP 需要。我几乎没在申请季前主动联系过导师，也没带着方案去请教 |
| 5 | **用自设的硬约束把自己框进空集** | 我坚持"只要基础难度、只要 ≤3 个月"，把本就不多的可用项目进一步筛没了 |

第 1、4 条是最要命的。它们共同指向一件事：**我把所有精力花在"自己卷"上，却从没让导师"提前认识我"。**

## 六、给下一次的清单（可执行）

1. **提前 2-3 个月选定项目**——挑"导师在仓库里活跃、且我能深挖"的项目，别等申请季才开始；
2. **在导师的项目本体上做小而聚焦的 PR**——一个真实的修复，比十个周边小修有价值，而且要在申请季之前留痕；
3. **申请季前主动给导师发邮件**——不是"我想申请"，而是"我在您的仓库做了 X，想确认方向是否合适"，带着可验证的产物敲门；
4. **申请书按"作战计划"写，不是"简历清单"**——但真正决定中签的仍是提前建立的信任；
5. **选项目要看信号**——避开门户高度内定的热门社区，找 issue/README 里"欢迎贡献/在招人"、导师真正缺人手的项目；
6. **别用硬约束把自己框死**——"只要基础难度、只要 ≤3 个月"这种条件叠加，会把所有可行项筛成空集；折中方向（标题不带 Agent、但底子里有 AI 应用层）可能是更现实的路。

## 七、没失去的

**失去的**：这一季的名额。仅此而已。

**没失去的**：

- 合入上游的 PR 是**永久**的，写在公开历史上；
- 那套跑通项目、复现 bug、提 PR 到合入的完整链路经验，换任何项目都能复用；
- 以及最重要的——**我看清了规则**。下一季，我不再是"第一次参加、没经验、从竞赛来的"那个人了。

## 后记：两篇复盘连起来，才是我对开源之夏的完整理解

上一篇复盘《[一次 OSPP 申请的事故复盘：技术做完了，我却没听懂导师要什么](/2026/08/26/ospp-application-retrospective/)》讲的是**单个课题**里，我输给了沟通失能——不敢问、不敢发信、把"能力演示"做成"成品报告"。

这一篇讲的是**整个申请季**，我输给了占坑游戏——用竞赛逻辑打了一场信任战争。

两篇合起来才是完整的一课：**开源之夏既是信任游戏，也是沟通游戏，唯独不是竞赛。** 竞赛拼提交，这里拼的是"你有没有让别人认识你、信任你、并提前看到你在干活"。

三行笨拙的真话，胜过三千字发不出去的草稿；提前三个月的三个 PR，胜过申请季临时卷出来的十个。

下一窗口，我先学会把话说出口，再把活干在导师面前。
