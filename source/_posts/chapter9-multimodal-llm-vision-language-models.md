传统语言模型的输入是 token 序列，而现实世界的信息还包括图像、音频、视频和传感器数据。多模态大语言模型的核心任务不是让模型“直接看到”图片，而是把不同模态转换成能彼此交流的表示，并让语言模型能够基于这些表示完成问答、描述和推理。

```text
图像 / 音频 / 视频
  → 模态编码器
  → 一串向量表示
  → 对齐或桥接模块
  → LLM 的上下文序列
  → 文本、结构化结果或动作
```

## 一、Transformer 处理的是向量序列

Transformer 并不限定输入必须是文字。文本经过 tokenizer 和 embedding 后是向量序列；只要图像或音频也能转换成有顺序的一组向量，Transformer 的注意力机制同样可以处理它们。

| 模态 | 原始数据 | 常见序列化方式 |
| --- | --- | --- |
| 文本 | 字符、子词 | token embedding 序列 |
| 图像 | 像素矩阵 | patch embedding 序列 |
| 音频 | 波形 | 时间帧或频谱 patch 序列 |
| 视频 | 图像帧序列 | 空间 patch 加时间位置编码 |

关键难点在于：不同模态的统计规律、尺度和长度差异很大。一个视觉编码器擅长提取颜色、形状和空间关系，不代表它输出的向量能直接被语言模型当作自然语言 token 理解。

## 二、ViT：把一张图像变成视觉 token

Vision Transformer（ViT）将图像切成固定大小的 patch。若输入图像大小为 (H × W)，patch 大小为 (P × P)，则大致得到 (N = (H / P) × (W / P)) 个 patch。每个 patch 展平后经线性层投影为向量，再加上位置编码：

```text
图像
  → 切成 16×16 等大小的 patch
  → 每个 patch 展平并线性投影
  → patch embeddings + position embeddings
  → Vision Transformer
```

这与文本 token 很像：一个 patch 是视觉中的局部单元，不一定对应一个完整物体；注意力层再把多个 patch 的信息整合成物体、场景和关系层面的表示。

Patch 大小影响效率与细粒度能力。更小的 patch 保留更多局部细节，却使序列变长，注意力计算更昂贵；更大的 patch 更高效，却可能损失文字、小物体或精细空间关系。

## 三、CLIP：让图片与文字能够相互比较

ViT 能得到图像特征，文本编码器能得到文本特征，但两套向量如果不对齐，就无法直接比较“这张图”与“a photo of a cat”。CLIP 使用图像编码器和文本编码器，将匹配图文拉近、不匹配图文推远：

```text
图片 ─→ Image Encoder ─→ image embedding ─┐
                                              ├→ 比较相似度
文本 ─→ Text Encoder  ─→ text embedding  ───┘
```

对于一个 batch 中的图文配对，对比学习会希望正确的图文相似度高于其他组合。常见形式是对归一化后的向量计算相似度，再用 batch 内其他样本构造负例。负例很重要：若只要求匹配对靠近，所有表示可能坍缩到近似同一个方向，模型学不到区分性。

### 1. Zero-shot 分类

CLIP 的图文对齐允许用文本描述动态定义类别：

```text
待分类图片 → 图像向量
“a photo of a cat” / “a photo of a dog” / “a photo of a car” → 文本向量
比较相似度 → 选择最高的描述
```

这不是“模型从未见过类别就一定能识别”，而是将分类从固定分类头改成图像与候选文本的匹配。提示模板、标签措辞和训练分布都会影响效果；在专业领域，仍可能需要领域数据或专用模型。

### 2. 图文检索

将图片向量离线写入索引，用户输入文本后编码为查询向量，即可检索语义相关图片；反向也可以用图片找相似图片或相关描述。这与第八章的语义搜索结构相同，只是向量空间变成跨模态的。

## 四、从“图文匹配”到“基于图像对话”

CLIP 很适合判断图文是否相关、进行检索或零样本分类，但它没有自回归语言模型的对话接口。要回答“图中是谁在做什么”“这张图能否支持某个结论”之类的问题，需要把视觉信息变成语言模型能利用的上下文表示。

```text
视觉编码器 → 视觉特征
           → 连接器 / 投影器
           → LLM 输入空间中的视觉 token
           → 用户文字 token
           → LLM 生成回答
```

连接器的作用是对齐表示空间与信息粒度。它不能只把向量维度从视觉 encoder 的维度改成 LLM 的维度，还要学习哪些视觉信息值得传递、怎样压缩成有限数量的视觉 token。

## 五、BLIP-2 与 Q-Former：冻结大模型之间的桥梁

BLIP-2 是一个典型思路：复用预训练视觉编码器和预训练 LLM，在中间训练较小的 Q-Former（Querying Transformer）与投影层。

```text
图像 → 冻结的视觉 Encoder → visual features
     → Q-Former 的可学习 query tokens
     → 投影层
     → 冻结的 LLM → 文本回答
```

Q-Former 通过一组可学习的 query tokens 从视觉特征中查询、压缩对语言任务有用的信息。它不是简单的格式转换器：用户可能关心物体、颜色、数量或相对关系，桥接模块需要把这些可供后续语言推理使用的线索带过去。

冻结大部分视觉 encoder 和 LLM，只训练桥接模块，能显著降低训练成本，也能复用强大的单模态预训练能力。代价是桥接容量可能成为瓶颈：过度压缩会遗失细节，且冻结组件的偏差也会被继承。

## 六、视觉 token 与 Soft Prompt

从 LLM 的角度看，连接器输出的一串向量可以被放在文字 token embedding 的前后。这些向量很像由图像条件化生成的 soft prompt：

```text
[visual token 1, visual token 2, ...] + [“请描述这张图” 的文本 token]
```

LLM 不需要直接处理像素；它接收的是已经映射到输入空间的一串连续向量。多模态模型的难点也因此转化为表示对齐与训练信号设计：这些视觉 token 是否足够保留问题所需的事实，又是否能被 LLM 正确解释。

## 七、训练目标各自解决什么

多模态模型通常不靠单一损失学会全部能力。常见训练信号可以分工理解：

| 目标 | 训练信号 | 主要作用 |
| --- | --- | --- |
| Image-Text Contrastive | 匹配图文比不匹配图文更相似 | 学跨模态检索与全局对齐 |
| Image-Text Matching | 判断图文是否配对 | 学更细的匹配判别 |
| Image-grounded Text Generation | 根据图像生成文本 | 让视觉表示服务于语言生成 |
| Instruction Tuning | 图像/文本指令到回答 | 学会多轮问答与任务格式 |

这些目标互补。对比学习得到“整体是否相关”并不自动带来细粒度定位能力；描述生成擅长概述，也不代表模型能可靠读出小字号文字或完成严谨的几何推理。

## 八、多模态 RAG 与 Agent 的工程边界

多模态知识库可为图片、PDF 页面、音频片段等建立索引，再将召回内容传给视觉语言模型。其基本链路是：

```text
多模态资料 → 解析、切分与元数据 → 向量/关键词索引
用户问题（文本或图像） → 跨模态检索 → 证据片段 → 多模态 LLM 回答
```

但“模型看到了图片”不等于输出可信。对票据、图表、医学影像、地图或安全敏感场景，需要保留原始来源、提供定位或引用、使用专门的 OCR/视觉算法校验，并在不确定时明确限制。多模态输入还扩大了提示注入和隐私风险：图片中的文字、文件元数据和嵌入内容都应视为不可信数据，而不是系统指令。

## 九、本章的三层框架

```text
ViT：    图像如何变成可被 Transformer 处理的 patch 向量序列
CLIP：   图像与文本如何进入能够比较的共同语义空间
BLIP-2：视觉信息如何经桥接模块变成 LLM 可用于生成与推理的视觉 token
```

多模态 LLM 的本质是表示转换与对齐：先保留各模态有用的结构，再让它们在共享或可桥接的向量空间中交流，最后由语言模型将这些证据组织成回答。模型能力的边界仍由训练数据、视觉分辨率、桥接容量、上下文预算和验证机制共同决定。
