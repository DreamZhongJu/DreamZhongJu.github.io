文本分类是“输入一段文本，输出一个或多个标签”的任务：情感分析、意图识别、垃圾邮件检测和文档归类都属于这一类。它很适合作为理解现代 NLP 范式变化的入口：同一个分类目标，今天可以由专用分类模型、向量模型，或生成式 LLM 来完成。

## 一、三条分类路线解决的是同一个问题

```text
文本分类：输入 x → 预测标签 y

路线 1：专用分类模型      x → Encoder → 句向量 → 分类头 → y
路线 2：Embedding + 分类器 x → Embedding → 向量 → 轻量分类器 → y
路线 3：生成式 LLM        指令 + x → Decoder → 生成标签文本
```

它们的区别不在于是否“懂文本”，而在于输出接口、训练成本、推理延迟和面对新标签时的泛化能力。

| 路线 | 主要输出 | 训练方式 | 典型优势 | 典型限制 |
| --- | --- | --- | --- | --- |
| BERT 等分类模型 | 固定类别上的 logits | 微调编码器和分类头 | 快、稳定、低成本 | 标签或任务变动时往往要重训 |
| Embedding + 分类器 | 语义向量后再分类 | 常冻结向量模型，只训练小分类器 | 数据少、迭代快 | 表示质量决定上限 |
| GPT/T5 等生成模型 | 标签对应的文本 token | Prompt、微调或指令微调 | 标签语义复杂时泛化好 | 延迟与成本更高，输出需约束 |

## 二、路线一：BERT 为什么适合固定分类任务

### 1. Encoder-only 模型得到的是双向上下文表示

BERT、RoBERTa 这类模型没有“从左到右继续写下一个 token”的因果限制。处理某个 token 时，它可以同时利用前后的 token。

```text
The bank is near the river.
        ↑
bank 同时参考前文和后面的 river，倾向“河岸”而非“金融机构”。
```

这使它特别适合判断“整段输入表达了什么”。常见的单标签分类头可以写成：

<div class="attention-formula" role="math">p(y | x) = softmax(W · h<sub>CLS</sub> + b)</div>

其中 `h_CLS` 是编码器最后一层中 `[CLS]` 位置的 hidden state，分类头将其投影到类别数大小的 logits，再经 softmax 得到每个类别的概率。

### 2. `[CLS]` 是如何变成句子摘要的

输入常写成：

```text
[CLS] I love this movie [SEP]
```

`[CLS]` 天生并不比其他 token 更会概括句子。它之所以能用于分类，是因为训练时分类损失从分类头反向传播到这个位置，持续要求它携带足以区分类别的信息。可以把它看成一个**由训练目标塑造出来的聚合槽位**。

`[SEP]` 的职责则是分隔句子、标记输入结构。例如句对分类可写成 `[CLS] sentence A [SEP] sentence B [SEP]`。它不是主要的句子语义汇总向量。

### 3. BERT 微调的工程边界

如果任务标签稳定、标注样本充足，且吞吐量和延迟重要，微调分类模型通常是很实用的选择。它一次前向传播就能给出固定类别上的分数，输出格式天然受约束。

代价是需要维护训练集、训练流程与模型版本；类别体系发生较大变化时，分类头维度和训练数据都要跟着调整。

## 三、路线二：Embedding 将文本放入语义空间

Embedding 是文本在连续向量空间中的表示，不是 token ID、概率或最终类别。一个文本经过嵌入模型后会得到类似下面的向量：

```text
“我喜欢这个手机” → [0.23, 0.56, ..., -0.17]
```

语义相近的文本通常被训练为在向量空间中更接近，因此可以使用余弦相似度：

<div class="attention-formula" role="math">cosine(a, b) = (a · b) / (||a|| · ||b||)</div>

### 1. 两种常见使用方式

**监督分类。** 固定 Embedding 模型，用已标注文本的向量训练 Logistic Regression、线性 SVM 或小型 MLP。此时训练的参数量很小，适合样本有限、需要快速试验的场景。

**原型或零样本分类。** 为每个类别准备描述性文本，例如“科技公司新闻”“水果与农产品”，计算输入与类别描述向量的相似度，选择最接近的一类。标签描述要足够明确；仅用“科技”“水果”这类极短词时，向量往往不如自然语言描述稳定。

```text
“苹果发布新手机” → 输入向量
“关于公司、产品和科技产业的新闻” → 科技标签向量
“关于水果、农作物和食品的内容” → 水果标签向量
比较相似度 → 选择更高者
```

Embedding 检索和分类的底层直觉相同：都在比较语义距离。差别是检索的候选是大量文档，分类的候选是有限类别或类别原型。

### 2. 何时它比端到端微调更合适

当标注数据少、类别经常新增、希望复用同一套向量服务做检索和分类，或者要先快速验证任务可行性时，Embedding 加轻量分类器往往成本更低。它也方便人工检查：可以直接查看一个样本离哪些类别原型最近。

但“冻结大模型”并不保证质量。若嵌入模型没有针对该语言、领域或任务训练，类别在向量空间里本身就难分，后面的简单分类器无法凭空补足这种信息。

## 四、路线三：生成式模型如何做分类

GPT 类模型本质上预测下一个 token，并没有一个固定的 `num_labels` 分类头。但只要把标签写成预期文本输出，分类就能改写成生成任务：

```text
任务：判断电影评论的情感，只输出 positive 或 negative。
评论：This movie is amazing.
答案：

→ 模型生成：positive
```

对于固定且很小的标签集合，可以比较候选标签 token 的条件概率；对于复杂标签、层级标签或需要解释的任务，则可以让模型生成结构化 JSON，并在应用层校验输出是否属于允许集合。

生成式分类的风险是模型可能输出额外解释、同义词或不在标签集里的内容。因此生产系统通常需要：明确的标签定义、少量示例、低温度，以及 JSON Schema 或枚举校验等输出约束。

## 五、T5：把所有任务统一成 text-to-text

T5（Text-to-Text Transfer Transformer）的设计主张是：翻译、摘要、问答和分类都可以表达为“输入一段文本，输出一段文本”。任务前缀告诉模型当前要做什么：

| 任务 | 输入 | 输出 |
| --- | --- | --- |
| 翻译 | `translate English to German: Hello` | `Hallo` |
| 摘要 | `summarize: 长文章` | 摘要文本 |
| 分类 | `sentiment: This movie is great` | `positive` |

### 1. Span Corruption 预训练

T5 的预训练常用 Span Corruption：随机替换连续的一段文本为特殊 sentinel token，再要求模型恢复被遮盖的片段。

```text
原文：I went to New York yesterday
输入：I went <extra_id_0>
目标：<extra_id_0> to New York yesterday
```

它不是普通的单 token Masked Language Modeling；连续片段的恢复要求模型利用更长的上下文。之后的下游任务仍可统一写作“任务描述 + 输入 → 输出文本”。

## 六、从 GPT 到 ChatGPT：预训练、指令微调与偏好对齐

“GPT 能续写”与“ChatGPT 能较可靠地完成指令”之间，通常还隔着后训练阶段。

### 1. 预训练：学习语言和世界中的统计规律

预训练使用大量文本，让模型学习下一个 token 预测。它获得语言模式、部分知识与模式归纳能力，但并不天然知道应该遵从用户的任务格式。

### 2. Instruction Tuning：学习任务接口

指令微调使用“指令—高质量回答”样本，例如“写一封邮件”对应一封完整邮件。它主要教会模型：用户输入中哪些部分是要求、应该采用什么输出结构、何时简洁或展开。

### 3. Preference Tuning：学习偏好排序

偏好数据不是单一标准答案，而是同一提示下多个回答的比较或排序，例如 `答案 B > 答案 A > 答案 C`。DPO、RLHF 等方法会让模型更倾向于人类偏好的回答。

| 阶段 | 数据 | 主要改变 |
| --- | --- | --- |
| 预训练 | 大规模原始文本 | 语言建模能力与广泛先验 |
| 指令微调 | 指令—回答对 | 执行任务和遵守输出格式的能力 |
| 偏好对齐 | 回答比较、排序或反馈 | 有用性、风格与安全边界等行为倾向 |

偏好对齐并不是把模型“训练得更懂所有事实”；它主要是在已有能力上选择更符合目标的回答方式。

## 七、BERT 分类与 GPT 分类为何读取不同位置

```text
BERT：文本 → 双向 Encoder → h_CLS → 分类头 → 固定类别
GPT： Prompt → 因果 Decoder → 最后位置 hidden state → LM Head → 标签 token
```

BERT 的目标是获得全序列表示，因此用 `[CLS]` 汇总整段输入；GPT 的目标是根据已有前缀预测下一个 token，因此以最后位置的 hidden state 作为输出接口。两者的“读哪个位置”由训练目标决定，不是某种实现习惯。

## 八、工程选型：先看约束，再选模型

| 情况 | 优先选择 | 原因 |
| --- | --- | --- |
| 标签固定、数据充足、高并发 | BERT/RoBERTa 微调 | 速度快、输出稳定、单位成本低 |
| 标注少、类别常变、需要快速验证 | Embedding + 轻量分类器/原型 | 训练与迭代成本低，便于排查 |
| 标签含义复杂、需要解释或跨任务泛化 | Prompt/微调后的生成式 LLM | 可利用自然语言任务描述和上下文 |
| 对格式有严格要求 | 分类头或受约束的 LLM 输出 | 避免自由生成越出标签集合 |

现代 LLM 的变化可以概括为：传统 NLP 经常是“一个任务配一套模型与头部”；而 text-to-text 和指令范式把任务描述、输入文本和输出文本放进统一接口。统一接口提高了迁移与复用能力，但并没有消除工程权衡。固定、高频、可明确定义的分类任务，专用模型依然可能是更好的答案。
